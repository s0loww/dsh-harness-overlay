# Каталог API: UI dev10

Установлено 2026-11-04. Policy остаётся 0.12.0-dev13.

Причина вечного «Загрузка каталога API…» — неверное чтение структуры
SlotCore: ID находится в entry.options.id, тогда как новая страница искала
entry.id. Контроллер Models поэтому не находился. Аналогичный доступ к
реестру затрагивал карточку аккаунта DeepSeek.

Страница теперь получает штатные controller/operations через observable bridge
из двух hash-pinned native client modules (Models и Account). Snapshot имеет
стабильную identity, поддерживает позднюю активацию и очистку владельца.
Реестр слотов больше не используется для получения render/inject internals.
При отсутствии контроллера через 8 секунд появляется ошибка с повтором.

Подтверждения:

- Полный набор 201/201 PASS. Регрессия воспроизведена на настоящем SlotCore
  rc.5 и actual patched Models.apply, а не только на mock metadata.
- Candidate08: rollback/reapply PASS, visible startup PASS.
- Live receipt: var/live-promotion-backups/release-20261104-api-ui10/receipt.json.
- Новый guarded update проверяет прежний receipt и состояния принадлежащих ему
  пакетов. Допускается только обновление с идентичными UI/policy fragments.
- Текущий пользовательский cordis.patch.yml сохранён побайтно; before==after
  подтверждено receipt и повторным чтением. Аккаунты и credential stores не
  входят в операции установки.
- Каталог API загрузился в живом интерфейсе, видны провайдеры и подключённый
  DeepSeek с двумя моделями. Пользователь подтвердил: «прогрузилось».
- Баланс в footer отображает обе валюты. Реальные запросы генерации через
  выбранные пользователем API в этой проверке не отправлялись.

Предыдущий receipt сохранён без изменения. После guarded update использовать
новый receipt для отката; пользовательские изменения старого профиля нельзя
откатывать через прежнюю цепочку, игнорируя проверку целостности.
