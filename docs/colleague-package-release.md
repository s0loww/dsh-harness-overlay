# Единый тестовый пакет для коллег

Актуальный TEST3 с исправлением обнаружения отсутствующего Docker описан в
[протоколе TEST3](deployment-bootstrap-test3.md). Состав Java и локального
BSL Language Server сохранён из [TEST2](deployment-linter-package.md).
Ниже сохранена приёмка TEST1; его архив не изменялся.

Дата: 2026-11-11. Статус: **готов к передаче на приёмочное тестирование**.
Код установщика: `a30ea13`. Пакет `0.17.2-test1`, Windows x64.

## Комплект

- Подписанный официальный DSH `0.2.2-rc.1`, UI `0.17.0-host022-ui1`,
  policy `0.17.2-approval1`, встроенные airules `0.16.0`.
- Полная существующая надстройка: настройки, провайдеры, пресеты 1С/Python/
  администрирования, OpenSpec, импорт, навыки, оркестрация, память, Telegram,
  обновление и раскатка правил, проверки и исполнители деплоя.
- Пять дополнительных плагинов с отдельными зависимостями; Капитан Дизель,
  модели Miara/Hiyori и настройки реплик. Исключённые пользователем блоки
  повторно не включались.
- Штатный локальный Cognee `1.6.7`: образ, модели, отдельные данные и новый
  локальный API-ключ получателя. Node, Python, MinGit, полные подписанные
  установщики Docker Desktop и WSL включены.
- Шесть согласованных публичных MCP и общий bearer-ключ. Привязки к рабочим
  проектам, личные аккаунты, чаты и существующая база памяти не копировались.

## Передача и запуск

Архив: `var/deployment-packages/airules-dsh-0.17.2-test1-20261111.zip`.
Размер: **3 257 461 843 байта**, примерно **3,03 ГиБ**.

SHA-256:
`83b66fbc3130b5cf6b973f5b82fd2ad863558ab21f702e6f007d549a225778b4`.
Контрольная сумма также записана в соседний `.zip.sha256`.

Распаковать весь архив и запустить **Setup.cmd** обычным пользователем.
После установки использовать ярлык **DSH Airules (тест)** или указанный
установщиком `LaunchDSH.cmd`. Собственные аккаунты провайдеров подключает
получатель. Инструкция и протокол проверки входят в архив.

Это приватный комплект для согласованной группы: внутри общий ключ MCP.
Архив, адреса инфраструктуры и provisioning-файлы в публичный Git не помещаются.
В Git хранится код; материалы сборки и диагностика остаются в игнорируемом `var/`.

## Первый приёмочный компьютер

Фактическая установка NSIS/Docker Desktop/WSL на полностью чистой Windows
ещё не проверена: официальный host в изолированной проверке копировался
из проверенного чистого дистрибутива, существующий Docker использовался повторно.
Установщики проверены по хешам и Authenticode; системный bootstrap покрыт
тестами, предусматривает интерактивные условия Docker и продолжение после
перезагрузки. Этот сценарий нужно подтвердить первым на машине коллеги.

Стандартная локальная embedding-модель английская; качество русских материалов
1С проверяется отдельно. Режимы и выбор других моделей доступны в настройках.

Протокол: [deployment-colleague-test.md](deployment-colleague-test.md).
Техническое устройство: [deployment-bundle.md](deployment-bundle.md).
