# Восстановление контекста: airules, проект БЛ и сборка Олега

Проверено 2026-11-10 по исходникам и изолированным проверкам. Рабочие настройки,
проектные данные и установленный DSH в этом аудите не менялись. Реальное сжатие
с вызовом модели не запускалось.

## Вывод

Основа у нас уже есть. Общий airules содержит событие напоминания о перечитывании
правил, восстановлении карты сессии и режима оркестрации. В БЛ есть отдельный
механический PreCompact-снимок. Эти механизмы нельзя записывать в план как
полностью отсутствующую функциональность. Для DSH пока отсутствует их native
адаптер: копирование правил/навыков не регистрирует события Python hooks.

У Олега есть дополнительное восстановление содержимого последних файлов и
инструкций, а также сведений о заданиях и файлах вывода. Это стоит добавлять к
нашему владельцу continuity, сохраняя общую политику airules.

## Что действительно подключено

- Claude project renderer/simulator: `ci/simulate_install.py:339` копирует общий
  rule-inject и регистрирует PreToolUse Edit/Write, SessionStart compact и
  startup/clear. Сам репозиторий airules в `.claude/settings.json` регистрирует
  только два SessionStart. Это регистрация и проверенный handler, не доказательство
  срабатывания на произвольной клиентской установке.
- Codex renderer: `targets/codex/render.py:355` и `hooks/config.py:11` формируют
  PreToolUse apply_patch/Edit/Write и SessionStart startup/resume/clear/compact/fork.
  Адаптер выдаёт native JSON, ограничивает контекст 4096 символами и проверяет
  границы проекта. Само наличие конфигурации не заменяет разрешение/trust клиента.
- DSH overlay: `src/official-preset/cordis.patch.yml:98` и domain presets используют
  native compaction-basic. `src/airules-provider/runtime.mjs` предоставляет
  постоянный контракт/индекс и инструменты правил/ролей, но не слушает события
  compact и не запускает Python reminders.
- Донор: `cordis.patch.yml:1028` монтирует context-restore; включение зависит от
  config.enabled, ONEC_CONTEXT_RESTORE и features пресета. Проверена поставляемая
  регистрация, не персональные переменные/работающий профиль донора.

## Найденный проектный PreCompact в БЛ

Исходник: `D:\AI_Projects\Project_BL\tools\context-snapshot\Context-Snapshot.ps1`.
Регистрация: `.claude/settings.local.json:49,67`.

Pre записывает `.claude/state/context-snapshot.md`: ветку, HEAD, пять коммитов,
git status, diffstat и число открытых/закрытых задач OpenSpec. Post вызывается
через SessionStart compact и возвращает сохранённый снимок вместе с первым
разделом `docs/СТАТУС.md`. Это механический checkpoint; смысловой статус остаётся
ответственностью агента. Автогенерация handoff внешней моделью была намеренно
отложена в решении БЛ от 2026-08-31.

Для общего переноса снимок нужно отвязать от `.claude/state`, абсолютного пути
БЛ и `docs/СТАТУС.md`. Нужны привязка к сеансу (сейчас один файл на репозиторий),
явный предел размера и проверка свежести. «Первый раздел статуса» уменьшает
объём, но не устанавливает жёсткий байтовый бюджет. Снимок не подтверждает
актуальность состояния и не должен автоматически выполнять checkout/reset.

## Что добавляет донор

`lib/context-restore.js:33` наблюдает успешные tool results, skill invocations
и prompt commands. На compaction/start фиксирует утрачиваемые Read, на end
отмечает pending только после успешного сжатия. В agent/pre-step после native
компактора добавляет сообщения восстановления.

- Файлы: максимум 5, до 8 КиБ каждый и 20 КиБ суммарно; текущие данные с диска.
  Ссылки/junction, служебные каталоги, binary и распознаваемые секреты исключаются.
  Крупные файлы заменяются указателем для точечного чтения.
- Инструкции: последние 3, до 8 КиБ на одну и 16 КиБ суммарно. Это ранее
  сохранённый текст, а не новое чтение источника. При переносе лучше сохранять
  идентификатор/версию и перечитывать изменившийся источник.
- Задания: до 20 running/stopping/queued и 5 spill/artifact-путей. Полный вывод
  артефактов не подмешивается.
- Штатному summarizer добавляется требование сохранять точные имена объектов,
  процедур, пути и ошибки. Второго компактора или платного вызова не создаётся.

Файловое восстановление для нашего DSH следует выполнять через native fs и
действующую sandbox policy, сохраняя область проекта и ограничения объёма.
Все извлечённые материалы остаются данными, а не новыми разрешениями.

## Исправления и замечания аудита

1. Предыдущее предположение о несовместимости `session.surface.nodes` с rc.5
   неверно. В pinned native dsh-session есть getter surface (`lib/index.js:1329`),
   и deriveMessages читает surface.nodes. Удалённый API — `session.nodes`.
2. Общий `rule-inject.py:107` по-прежнему требует всегда спрашивать о продолжении
   найденного handoff. Текущее `core/rules/session-handoff.md:138` требует вопроса
   только при неоднозначности; уже выбранная/активная задача продолжается.
   Codex adapter это уже учитывает. Текст Claude notice нужно согласовать.
3. Утверждение старого комментария БЛ «PostCompact нет» — историческое. В текущей
   официальной документации Claude Code PostCompact уже существует. Это не
   повод менять работающий SessionStart compact: назначение событий и доставка
   контекста различаются. Локальный CLI сообщает версию 2.1.296.

Актуальная официальная схема командных hooks допускает command + args, как в
нашей регистрации: https://code.claude.com/docs/en/hooks#command-hook-fields.
События: https://code.claude.com/docs/en/hooks#postcompact.
