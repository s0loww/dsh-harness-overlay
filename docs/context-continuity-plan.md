# Единое восстановление контекста airules

Проект решения, 2026-11-10. Это план следующего изменения, не описание уже
установленного hook. Исходная проверка — `context-continuity-comparison.md`.
Работа с Cognee выпускается отдельно: она не является зависимостью continuity.

## Рекомендуемое решение

Оставить airules владельцем правил, режима оркестрации, карты сессии и handoff.
Обобщить механический снимок БЛ и дополнить его ограниченным восстановлением
утраченных файлов, реестра заданий и ссылок на артефакты из реализации Олега.
Встроить это в **один** обработчик восстановления на целевой harness. В DSH
сохранить штатный compaction-basic: второй summarizer не нужен.

По умолчанию возвращать небольшой проверяемый пакет: напоминание о правилах,
ссылки на состояние задачи и receipts актуальности. Содержимое файлов
восстанавливать отдельной opt-in настройкой; тексты всех правил/навыков не
загружать. Уже выбранная пользователем задача продолжается с
сохранением действующих разрешений; новый вопрос нужен лишь при неоднозначности
задачи/владельца/существенного действия, которую нельзя разрешить из контекста.

## Владельцы и три разных вида состояния

| Слой | Содержимое | Владелец и срок жизни |
|---|---|---|
| Контракт | Правила восстановления, бюджет, происхождение, полномочия | Canonical airules; рендерится в целевой пакет |
| Рабочая continuity | Сеанс, поколение compact, пути последних Read, ID навыков, task/job/artifact receipts | Adapter текущего сеанса; не глобальный кеш всех проектов |
| Механический checkpoint | Проверенные Git/файловые метаданные, пути карты/состояния и время снимка | Изолированное состояние конкретного сеанса; не смысловой отчёт |
| Handoff и карта результатов | Проверенные выводы агента с базой/источниками и актуальными ссылками | По существующим `session-handoff.md` и `session-map.md`; карту пишет основной агент |
| Долговременная память | Подтверждённые переиспользуемые факты/решения | Выбранный memory backend по действующей политике; compact ничего туда не пишет |

Субагент получает только собственную continuity. Он не меняет общую карту,
режим основного агента или память. Изменение native origin/parentSession не
подменяется полем из сохранённого JSON. Короткие задачи субагентов и прежняя
политика пересоздания до compact сохраняются.

## Общий контракт и данные

В canonical airules добавить спецификацию/schema continuity и проверочные
fixtures. Для каждого входа фиксировать `projectKey`, `sessionId`, `taskId` при
наличии, роль владельца, source event/call ID, поколение surface и время проверки.
Компакт идентифицировать своим native ID, не временем последнего сообщения.

Checkpoint содержит: schema version, root identity, branch/HEAD, ограниченный
список изменённых путей и diffstat, пути карты/оркестрации/статуса, версию или
hash этих источников, состояние сбора (`complete/partial/unavailable`) и причины
ограничения. Полные diff, тела исходников, секреты, транскрипт и непроверенные
выводы в checkpoint не сохраняются. Поля branch/HEAD — факт снимка, не команда
вернуть Git в это состояние. Права/approvals не восстанавливаются из файла.

Состояние хранить раздельно по проекту **и сеансу**. Схема пути для разрешённой
проектной записи: `var/tmp/continuity/<sessionKey>/checkpoint.json`; ключ —
непользовательский безопасный ID или его hash. Старый общий
`.claude/state/context-snapshot.md` БЛ не переиспользовать несколькими сеансами.
Запись — bounded temporary file + atomic rename, без удаления чужих файлов.

Для read-only не выдавать дополнительных прав. Если harness предоставляет
проверенное native session-state storage, использовать его по его контракту;
иначе оставить transient receipts и явно сообщить отсутствие durable checkpoint.
Существующий журнал DSH сохраняется самим DSH; новая запись произвольного event
через `session.append()` не считается допустимой без проверки native schema.

Едины контракт, данные политики и fixture-оракул, а не обязательный интерпретатор.
Python hooks Claude/Codex и native JS DSH имеют разные transport adapters.
Не вводить зависимость standalone DSH от установленного Python и не запускать
внешнюю CLI ради каждого напоминания. Правила/алгоритмические решения не должны
расходиться между адаптерами: одинаковые входы проверяются общими fixtures.

## Жизненный цикл

1. **Обычная работа.** Наблюдать только успешные native Read/skill results и
   артефакты. Сохранять ID, область, версии и границы прочитанного, а не весь
   tool output. Поддерживать недорогой checkpoint на разрешённых границах шагов.
   Отдельный сбор Git/OpenSpec имеет свой короткий timeout и явный partial.
2. **Начало compact.** Зафиксировать receipt набора утрачиваемых успешных чтений,
   ID compact и generation. Не дописывать смысловой handoff и не вызывать LLM.
   Обновление checkpoint до этого события не выдавать за точный снимок события.
3. **Завершение compact.** Пакет допускается только после успешного завершения
   того же ID. Ошибка/отмена оставляет обычное состояние без ложного восстановления.
   После рестарта незавершённый compact проверяется по native lifecycle, а не
   истолковывается как успешный из наличия checkpoint.
4. **Первый последующий запрос.** Определить, какие источники реально исчезли,
   проверить текущие session/root/preset/policy, собрать пакет в пределах общего
   бюджета и передать его один раз для этого поколения. Уже оставшееся не дублировать.
5. **Новый сеанс/handoff.** Обнаружить подходящие документы и сверить текущие
   branch/HEAD/пути. Не продолжать случайный старый handoff, но и не спрашивать
   повторно об уже выбранной задаче из-за самого факта восстановления.

### Важное ограничение native DSH rc.5

`dsh-compaction-basic/lib/index.js:437–495` синхронно добавляет compaction/start
как lock перед асинхронным summarizer. `session/event` — уведомление, а не
подтверждённый awaited PreCompact gate. Поэтому нельзя перенести асинхронный
Git-снимок БЛ в listener и объявить, что summarizer дождался его записи.

Для DSH первая версия делает синхронный bounded capture уже собранных receipts,
использует последний завершённый checkpoint с его настоящим timestamp и обновляет
механические данные отдельно. Требование строго точного awaited precompact
checkpoint допускается только после проверки/добавления публичного native gate;
не monkeypatch compactor. Это не блокер для reminder и последующего свежего Read.

`session.surface.nodes` существует в pinned rc.5. Для определения retained
источников можно использовать проверенный surface/события; `session.nodes`
использовать нельзя. Реестр delivery хранить по поколениям и проверять ошибки
compact; не сбрасывать его при произвольном входящем сообщении.

## Что именно возвращать

| Источник | Поведение по умолчанию |
|---|---|
| Правила | Прежние тела считать незагруженными; вернуть короткий инвариант и доступные ID/пути. Следующее зависимое действие требует актуального чтения |
| Оркестрация | Основному агенту — ссылка на своё состояние; сначала прочитать его перед делегированием. Субагенту не возвращать родительский режим как собственный |
| Карта | Ссылка на выбранную задачу/карту и её базу. При нескольких несвязанных картах без активной задачи — выбрать явно |
| Git/OpenSpec/статус | Краткие механические данные с timestamp и признаком fresh/stale/partial. Для статуса использовать настроенный путь/раздел, не `docs/СТАТУС.md` как универсальную константу |
| Недавние файлы | По умолчанию ID/путь/версия и просьба перечитать при зависимости. В opt-in режиме — только успешно читанные, утраченные и всё ещё допустимые файлы текущего проекта, отмеченные в явном контексте задачи как нужные для продолжения. Свежий Read через native fs; версия до/после. Большие/недоступные — ссылка и причина |
| Навыки/промпты | ID + текущая версия и просьба загрузить нужное. Кешированное тело донора автоматически не возвращать; optional body restore требует актуального resolver и проверки версии |
| Задания | Только текущие native jobs этого владельца: ID/status. Не возобновлять/повторять действие из записанного snapshot |
| Артефакты | До пяти допустимых ссылок с происхождением. Полные spill и файлы вывода не подмешивать автоматически |

Чтение соблюдает **текущую** policy, а не разрешение, бывшее во время прежнего
Read. Не использовать прямые `fs.readFileSync` донора для обхода native fs.
Path traversal/junction/выход из root и защищённые файлы отклоняются; denylist
секретов — дополнительная проверка, а не замена sandbox. Текст исходников и
восстановленных документов маркируется как данные, не как новые инструкции.

## Бюджеты и режимы

Предлагаемый default — `minimal`: только указатели, версии и reminder, общий
максимум **4 КиБ UTF-8**. Полные правила/навыки остаются на lazy re-read;
автоматического возвращения исходников нет. Это сохраняет смысл нашей экономной
оркестрации и не оплачивает повторно до 36 КиБ донорского восстановления.

Явно включаемый `balanced` имеет общий максимум **12 КиБ UTF-8** на один
пакет восстановления. В него включаются заголовки, пути и служебные поля:

- reminder/проверки области/ссылки карты и режима — приоритет первыми;
- механический checkpoint/статус — до 4 КиБ;
- до 2 свежих task-critical файлов, каждый целиком не более 2 КиБ (итого до 4 КиБ);
- оставшийся бюджет — ID навыков, до 10 текущих jobs, до 5 artifact references.

При переполнении сначала удалять тела файлов, затем второстепенные сведения;
оставлять ограничения и ссылки, а не обрезать середину инструкции. Не называть
КиБ токенами: это переносимый жёсткий byte cap. Native meter отдельно проверяет,
что восстановление не запускает цикл немедленного повторного compact.

`expanded` — явная настройка с верхним общим пределом 36 КиБ; donor limits не складываются сверх
него. `off` отключает автоматическую доставку, не удаляя checkpoint/handoff.
Ни один режим не включает память, внешнюю модель или изменение прав.

## Адаптеры и честные capabilities

| Target | Проверенная основа | Что добавить/не предполагать |
|---|---|---|
| Claude | Существующие PreToolUse и SessionStart compact; проектный БЛ PreCompact | Обобщить snapshot и согласовать общий HANDOFF_NOTICE с правилом продолжения. События/выход проверять на поддерживаемой версии; не переносить старое утверждение «PostCompact нет» |
| Codex | Renderer уже формирует PreToolUse + SessionStart и JSON additionalContext | Поддержку дополнительного before-compact события не объявлять из названия Claude hook. Если события нет — checkpoint на доступных границах + reminder, capability partial |
| DSH rc.5 | Session lifecycle compact/start/end, agent/pre-step, native tools/surface/jobs | Один composition-scoped continuity adapter; после await native step восстанавливать один пакет. Учесть manual compact и overflow-recovery, не только pressure |

Capabilities показывают отдельно: events registered, runtime permission/trust,
durable checkpoint, fresh-file restore, instruction resolver, exact compact ID.
Наличие файла настройки не выдаётся за успешное живое срабатывание.

## Очерёдность реализации и приёмка

1. **Canonical основа.** Schema/policy/fixtures в airules; исправить устаревший
   HANDOFF_NOTICE, нейтрализовать BL-specific пути. Проверить Claude/Codex render,
   сохранение пользовательских hooks и отсутствие лишних подтверждений.
2. **DSH minimal.** Подключить reminders, выбранную карту/режим, per-session
   receipts и native lifecycle. Не добавлять автоматическое чтение файлов до
   подтверждения scope/readonly/cancellation tests. Удалить дублирующие mounts.
3. **Checkpoint + bounded restore.** Подключить механический сбор, native fs,
   jobs/artifact references и два малых файла. Delivery receipts и generation
   проверять на повторном compact, рестарте и смене проекта. Skill bodies оставить
   opt-in до проверки текущего resolver.
4. **Модельная приёмка.** На изолированных данных DeepSeek Flash 4.1 High и
   Sol 6.1 Medium, каждый с MCP и без. Заранее показать задания/стоимость запроса.
   Проверить делегирование: основной агент восстанавливает карту/режим, субагент
   не пишет в общую карту/память и не принимает родительский режим за свой.

Основные регрессии: два сеанса одного проекта не перезаписывают checkpoint;
уже retained материал не дублируется; неуспешный/отменённый compact не даёт restore;
изменённые правило/skill не возвращаются старым текстом; изменённый файл читается
свежим и помечается новой версией; смена policy/root блокирует прежнее чтение;
большой файл/секрет/ссылка не обходят native guard; timeout механического сбора
даёт partial без остановки разрешённой независимой работы; duplicate delivery
не запускает цикл compact; Git-state mismatch не вызывает reset/checkout/stash.

До платной модельной проверки — fixture suite и настоящий native host probe без
модели: lifecycle replay, manual/auto/overflow distinction, sandbox/approval,
две конкурентные сессии, бюджет и causal receipts. Реальные проекты и деплой
1С для приёмки continuity не требуются.

## Чего не переносить вторым владельцем

Не переносить donor prompt router вместо airules, кеш всех правил/навыков,
автогенерацию смыслового handoff по сжатой сводке, отдельный compactor и memory
distillation на compact. Не считать replay сохранённых текстов свидетельством
актуальности источника. `history_search/history_read` остаётся отдельным
инструментом поиска доказательств; continuity может дать на него ссылку, но
не сканирует весь транскрипт автоматически и не превращает его в долговременную
память.
