# Исполнитель деплоя — policy dev21

Дата: 2026-11-05. Установлены UI dev14 / policy dev21 для DSH Desktop rc.5.
Активный режим по умолчанию: **fixture-only**. Реальный деплой не запускался.

## Реализовано

Исполнение теперь проходит полный путь: зарегистрированный проектный сценарий →
сохранённый план → проверка владельца, исходников, профиля и кода runner → блокировка
вычисленной цели → native sandbox/subprocess DSH → связанный отчёт применения →
результат и история. MCP-фасад и отдельный сервер для этого не нужны.

Применение реализовано отдельным адаптером `deploy-apply`, а не shell-строкой из
проектного JSON. У `agent-1c` фиксированы команда `deploy`, ключ `-Apply` и поля
контекста WorkflowRunId/StepId/SourceDigest/TargetDigest/ProfileDigest/ExactBuild/
TargetPath. Проект не может добавлять произвольные аргументы или сам выдать доверие
к коду. Версия runner должна входить в проверенный комплект или быть отдельно
проверена и зарегистрирована на машине.

Первый предметный адаптер поддерживает **прямо указанную файловую базу 1С**
test/development. До изменений runner проверяет хеш профиля, фактически выбранный
build платформы (каталог и числовые компоненты версии бинаря), совпадение разрешённой
цели с разрешёнными credentials и отсутствие reparse-путей. Production, серверный
target, старый runner без протокола и неоднозначная цель не исполняются.

Отчёт находится в новом каталоге `<resultDir>/workflow-<runId>/<stepId>/result.json`.
Проверяются свежесть и все идентификаторы запуска, профиля, исходников и цели,
состояние применения и завершающий шаг runner. **Exit code 0 без подтверждения
не даёт PASS.** Произвольные сообщения и командные строки из отчёта не выдаются
модели. PASS означает технически подтверждённое выполнение обновления runner,
а не функциональную приёмку конфигурации.

При отмене завершается собственный managed handle. При неизвестном результате,
потерянном/чужом отчёте, частичном выполнении или неподтверждённом завершении
сохраняются неопределённое состояние и блокировка цели. Автоматического повтора
или отката нет. Подтверждённая ошибка до изменений отличается от применения с
последующей ошибкой; состояние применения не теряется.

## Режимы

Машинная настройка плагина `airules-workflows`: `deployMode`.

| Значение | Что разрешено |
|---|---|
| `fixture-only` (по умолчанию, установлено сейчас) | Проверки и встроенная заглушка deploy-apply. Реальный runner заблокирован. |
| `disabled` | Проверки; применение и заглушка выключены. |
| `enabled` | Проверки, заглушка и явно настроенный проверенный реальный адаптер. Права и sandbox сеанса по-прежнему обязательны. |

Проектный binding не меняет машинный режим. HTTP настроек по-прежнему не запускает
процессы: выполнение доступно scoped tool `airules_workflow_run` активного агента.
Настройка и планирование сами по себе не означают поручения выполнить реальный
деплой. В ходе этого выпуска режим `enabled` проверялся только с mock transport.

В реальном сценарии apply-шаг ссылается на свой runner как на resource:
`resources: ["runner-onec"]`, где `runner-onec` — ключ в `runners` и `adapterId`
соответствующего provider. Исполнитель сам вычисляет идентификатор и класс цели,
а не принимает их из произвольного resource-описания. `sourcePaths` должен включать
sourceDir профиля; `configPaths` — `agent-1c.json`. Подключать следует обновлённый
канонический runner с Workflow-протоколом. Рабочие проекты этим выпуском не менялись.

## Проверка на заглушках

Встроенный `deploy-fixture` использует тот же adapter/host/native subprocess,
но вызывает только поставляемый fixture-скрипт. Он пишет тестовый маркер и отчёт
в `.airules/workflow-fixture-reports` проекта; не использует 1С, credentials, базы,
сервисы или проектные runners. В мастере доступен выбор **«Заглушка деплоя — без
1С и баз»**; он формирует сценарий для сохранения агентом с обычными правами DSH.
Если binding уже есть, требуется сравнение и объединение сценариев.

На настоящем runtime rc.5, в workspace-write изолированного кандидата, прошли:

| fail-before | FAIL | not-applied | снята |
| partial | INDETERMINATE | unknown | сохранена |
| no-report | INDETERMINATE | unknown | сохранена |
| stale | INDETERMINATE | unknown | сохранена |
| timeout | INDETERMINATE | unknown | сохранена |

Отчёт: `var/candidate/official-desktop-rc5-12/smoke/workflow-deploy-fixtures.json`.
Дополнительные тесты проверяют повтор запроса без второго запуска, изменение
исходников, принадлежность цели/сеанса, отсутствие прав, подмену путей и отчётов,
а также реальную ветку адаптера через подменённый transport без запуска 1С.
