# TEST3: исправление первой установки Docker и DSH

Дата: 13 ноября 2026. Пакет `0.17.2-test3`, официальный host `0.2.2-rc.1`,
UI `0.17.0-host022-ui1`, policy `0.17.3-linter1`. Состав TEST2 сохранён:
наши дополнения, правила, Cognee с моделями, MCP, Java и BSL Language Server.

## Исправления

- `WINDOWS_HOST_PROBE` выдаёт пути Docker CLI и Desktop как строки либо `null`.
  JavaScript проверяет тип перед обработкой пути; объект, массив, число или
  boolean отвергаются с `BOOTSTRAP_HOST_PROBE_INVALID`.
- Проверки подписей Docker, WSL и официального DSH явно загружают системный
  `Microsoft.PowerShell.Security` из `$PSHOME` и используют квалифицированный
  `Get-AuthenticodeSignature`. Наследованный `PSModulePath` из PowerShell 7
  больше не определяет, какой модуль проверяет подпись. Проверки SHA, доверия
  и закреплённого сертификата сохранены.

Исправления исходников: `97b16c7`, `5607c2b`, `badf1b8`.

## Граница проверки

Это проверка реальных процессов PowerShell, подписей поставляемых бинарников,
пакетного движка и целостности передачи. Наличие Docker и характеристики
«чистой машины» подменялись фикстурами; запуск установщика в позитивных тестах
заменялся callback-функцией. Полная установка Docker/WSL/NSIS на чистой ОС
не выполнялась и остаётся ручной приёмкой у получателя. Рабочие проекты,
пользовательская установка DSH и службы не изменялись. Реальный деплой 1С
и платные запросы моделей не запускались.
