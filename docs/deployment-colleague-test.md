# Короткая приёмка тестовой сборки DSH

Пакет **0.17.2-test1**: подписанный DSH **0.2.2-rc.1**, интерфейс
**0.17.0-host022-ui1**, правила **0.16.0**, policy **0.17.2-approval1**.
Проверять на отдельном тестовом проекте. Реальный деплой и обновление рабочих
баз в эту приёмку не входят.

Нужны Windows 11 x64, поддерживаемая сборка **22631 или новее**, включённая
виртуализация, от **8 ГБ RAM** и **20 ГБ свободного места**. Установка системных
компонентов может запросить права администратора и перезагрузку. После
перезагрузки повторно запустите `Setup.cmd`. Открытый Desktop DSH перед
обновлением нужно закрыть.

| Шаг | Что проверить | Ожидаемый результат |
|---|---|---|
| 1. Первый Setup | Распаковать полный пакет в отдельную папку и запустить `Setup.cmd`. Пройти предложенную настройку Docker, если он отсутствует. | Установщик показывает этапы, проверяет компоненты и сообщает итог. Docker работает в режиме Linux containers. При требовании перезагрузки есть понятное продолжение. |
| 2. Запуск и вход | Открыть DSH через ярлык «DSH Airules (тест)» или `LaunchDSH.cmd`, путь к которому сообщил установщик. Самостоятельно подключить свой аккаунт провайдера или API-доступ. | Русский интерфейс; чужих аккаунтов, чатов, проектов и заметок нет. Доступы вводятся самим тестером. |
| 3. Провайдеры и модели | Открыть карточку своего провайдера, обновить модели. Отправить короткий запрос. Изменить уровень рассуждений прямо в чате. | Модель отвечает; выбранный уровень меняется и сохраняется в этом чате. Ошибки подключения объясняются в интерфейсе. |
| 4. Проект и пресеты | Создать тестовый проект, выбрать `1С`; отдельно открыть Python и системное администрирование. Посмотреть настройки проекта 1С. | Каждый пресет доступен со своими правилами и навыками. Настройки выбранного проекта сохраняются после переключения на другой проект. |
| 5. Правила и импорт | На копии проекта открыть «Импорт из других агентов». Просмотреть тестовый файл инструкций и небольшой навык, импортировать выбранное. | Есть предварительный просмотр и выбор. Навык появляется в каталоге и загружается по запросу. Проектные переопределения правил учитываются. |
| 6. Штатный edit и BOM | В тестовом BSL-файле с UTF-8 BOM попросить изменить только один комментарий штатным редактированием. Сравнить diff и первые байты файла. | Изменён нужный комментарий; BOM `EF BB BF` и переводы строк сохранены. |
| 7. Делегирование без MCP | С отключёнными MCP попросить ведущего агента поручить субагенту чтение двух тестовых файлов и сверить его вывод. | Делегирование видно в траектории; субагент возвращает результат, ведущий проверяет его. Нет заявления о несуществовавших MCP-вызовах. |
| 8. Делегирование с MCP | Включить проектные MCP и повторить короткую задачу с чтением доступной документации или тестовых метаданных. | Видны реальные вызовы и результаты. Область проекта сохраняется. Отсутствующий инструмент даёт явное ограничение. Деплой не запускается. |
| 9. Cognee | В «Память» проверить подключение, сохранить синтетическую заметку с уникальной меткой, запустить обработку. Затем открыть документы, поиск и граф. | Сохранение, начало обработки и готовность различаются. После завершения поиск возвращает метку и источник, документ и граф относятся к выбранному проекту. |
| 10. Права памяти | Проверить «Подтверждения операций памяти»: обязательные, затем «Не запрашивать». В режиме только чтения повторить попытку сохранения. | Переключатель управляет дополнительными подтверждениями. Режим только чтения блокирует запись при любом положении переключателя. Переключатель не разрешает удаление памяти. Вернуть выбранную тестером политику. |
| 11. Перезапуск | Закрыть и снова открыть DSH. При возможности отдельно остановить и запустить только тестовый Cognee. Проверить заметку и настройки. | Проекты, настройки и собственная тестовая память сохраняются. При недоступности сервиса видна ошибка, после запуска поиск восстанавливается. |
| 12. Пет | Проверить показ/скрытие Капитана Дизеля или поставляемого пета и повторный запуск приложения. | Персонаж отображается, управление работает, настройка сохраняется. |

Для шагов 6–8 желательно пройти четыре сочетания: **DeepSeek V4.1 Flash / High**
и **Sol 6.1 / Medium**, каждую без MCP и с MCP. Используйте доступные вашему
аккаунту модели и короткие задачи. Если нужной модели или MCP нет, отметьте
проверку как «не выполнена», а не PASS.

В отчёте достаточно версии Windows, объёма RAM, результата каждого шага
`PASS / FAIL / не выполнено`, выбранной модели и краткого воспроизведения ошибки.
Прикладывайте обезличенные скриншоты и диагностику установщика. Удаляйте из них
аккаунты, адреса подключений, ключи, токены и содержимое личных проектов.

Проверки пакета и локального offline Cognee выполнены на машине разработчика.
**Установка prerequisite-компонентов на полностью чистой Windows/VM ещё не
подтверждена** — первый чистый компьютер особенно важен для этого шага.
Стандартная embedding-модель английская; качество поиска по русским материалам
1С оценивается отдельно от исправности установки и сохранности памяти.
