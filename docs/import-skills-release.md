# Импорт инструкций и управление навыками — UI dev15 / policy dev27

Дата: 2026-11-05. Установлено в DSH Desktop 0.2.1-rc.5: UI dev15 / policy dev27.

В настройках добавлены «Контекст и история → Импорт из других агентов» и «Навыки».
Старые ссылки на штатный раздел навыков открывают новую страницу без дублирования
пунктов меню. Используется штатное хранилище и приоритеты DSH.

## Импорт

Источники: Claude Code, Codex, Cursor и OpenCode, их стандартные каталоги выбранного
проекта или пользователя. Предпросмотр показывает инструкции, назначения, состав
файлов и конфликты. Существующие проектные AGENTS.md/CLAUDE.md, уже читаемые DSH,
повторно не переносятся. Правила из каталогов добавляются отдельными блоками в
AGENTS.md с сохранением текущих инструкций; условия применимости MDC показаны и
сохранены в тексте блока. Это перенос указаний модели, не движка glob-правил Cursor.

Применение повторно проверяет хеши источника и назначения, сохраняет резервную
копию и receipt в DSH_HOME/agent-import/backups. Конфликты требуют ручного разбора;
замены существующих навыков нет. Неполный импорт при ошибке явно сообщается;
оставшиеся файлы можно проверить в новом предпросмотре.

Навыки копируются вместе с документацией, изображениями и текстовыми скриптами.
Скрипты не исполняются и зависимости не устанавливаются. Навык со скриптами
первоначально выключен; включение доступно на странице навыков. Ссылки, бинарные
программы и предполагаемые секреты блокируют импорт пакета целиком. MCP, аккаунты,
чаты и настройки авторизации не импортируются.

## Навыки

Поиск, общая/проектная область, карточки, просмотр исходного SKILL.md, создание,
индивидуальное и массовое включение/выключение, обновление и открытие каталога.
Для проектных изменений нужны штатные права workspace-write, для общих —
danger-full-access. Права приложения автоматически не повышаются.

Выключение сохраняет исходные байты в SKILL.md.disabled и создаёт native policy
shadow с запретом model/user invocation. Это также предотвращает неожиданное
включение одноимённого встроенного навыка. Включение проверяет SHA и восстанавливает
исходник. Встроенные навыки отключаются пользовательским shadow без изменения
файлов установки. Навыки кода плагинов и вручную запрещённые политики показываются
для просмотра с объяснением ограничения.

Отдельные назначения навыков по типам задач из сборки Олега в этот инкремент не
входят: их runtime связан с его full-пресетом. Аудит показал, что это фильтрация
каталога подсказок по ask/plan/build и doc/spec/analysis/bugfix/full, не настройки
моделей ролей. Для последующего переноса нужен адаптер к нашей оркестрации.

## Проверка

- 436 тестов overlay прошли, включая настоящий SkillRegistry, filesystem provider
  и запрет вызова штатного skill.execute для выключенного навыка.
- Изолированный native DSH: 45 проверок HTTP/CSRF, импорта, CAS, дедупликации,
  сохранности ресурсов, доступности навыков и ограничений прав прошли.
- В браузере: предпросмотр → выбор → импорт двух записей → появление навыка;
  выключение/включение с просмотром исходника; создание и поиск нового навыка.
- Цепочка навыка с Python-ресурсом проверена целиком: импорт выключенным → просмотр
  оригинала → явное включение → native invocation; скрипт не выполнялся.
- Проверка install/rollback/reapply пакета и visible startup прошла на candidate17.
- В установленном профиле подтверждены все 43 операции, нулевой дрейф и целостность
  receipt; cleanupPending пуст. Официальный baseline сохранён (5/5 файлов).
- Модели, рабочие проекты, MCP и реальные деплои не запускались.

Evidence: var/import-skills-release-tests.log и
var/candidate/official-desktop-rc5-17/smoke/import-skills-native-summary.json.

Receipt установки:
`var/live-promotion-backups/release-20261105-import-skills-policy27/receipt.json`.
Пакет policy содержит 22 компонента и 5055 файлов; UI — 592 файла. Аккаунты,
проектные подключения, права и конфигурация исполнителя workflows сохранены.
