# Среда 1С, модели ролей и предметные пресеты

Установлено 2026-11-04: UI `0.1.0-dev13`, policy `0.12.0-dev15`,
официальный DSH `0.2.1-rc.5`. Сценарий выполнения задачи на БКИ пропущен
по прямому указанию пользователя. Deploy и исключённые блоки не включались.

## Среда и настройки 1С

Новая страница «Среда 1С» по явной команде проверяет локальные платформы,
зарегистрированные базы, XML/EDT-исходники и доступные инструменты.
В live-интерфейсе обнаружены 3 платформы, 14 записей баз и исходники XML.
1С, COM, базы и внешние команды при сканировании не запускаются.
Сетевые каталоги/реестр не обходятся; неизвестная установка допускает ручной
ввод пути. Отсутствие инструмента в стандартных местах не считается его
отсутствием на машине вообще.

Настройки проекта позволяют выбрать найденную базу/платформу и отдельно
просмотреть предложения по параметрам существующего проекта. Выбор и
предложения меняют только черновик; запись производится существующей кнопкой
Save с native permissions, CSRF, CAS и защищённой резервной копией. Помощник
не создаёт чужие правила, MCP или новое подключение к базе.

## Роли и ротация

Страница «Модели для ролей 1С» содержит точные 13 ролей project_rules и
реальный каталог подключённых моделей. Live-проверка показала DeepSeek,
OpenAI OAuth и Grok. У каждой роли можно выбрать model/effort; по умолчанию
наследуется модель родителя. Настройки пользователя не задавались за него.

Новый composition-scoped `airules_delegate(role, task, cwd?)` проверяет persona
встроенного rulepack и запускает native spawn с реальной привязкой. Чтение
persona через airules_role само по себе модель не меняет. Права, ограничения
глубины и наследование бюджета остаются штатными. Инструмент отсутствует в
Standard, Python и Sysadmin.

«Ротация моделей» создаёт отдельные явно включаемые текстовые пулы. Допускаются
совместимые модели одного провайдера/адаптера с подтверждённым протоколом
(PiAiAdapter или CodexAdapter этой сборки). Новые сеансы распределяются по
очереди; после начала вывода модель фиксируется. Необязательный failover
допускается только для временной ошибки до вывода; частичный ответ не
повторяется. Межпровайдерное переключение и изображения в пуле не заявлены.
По умолчанию пулов нет, ротация выключена; действующие аккаунты не меняются.

## Python и системное администрирование

Зарегистрированы native-пресеты `python-airules` и `sysadmin-airules` на полной
композиции Standard rc.5. Preset по умолчанию остаётся 1С. В live-настройках
видны оба новых пресета. В них нет rulepack 1С и управляемого 1С-делегирования.

6 правил и 4 skills загружаются лениво. Canonical source:
`project_rules/overlays/python/{rules,skills}` и
`project_rules/overlays/sysadmin/{rules,skills}`. Builder требует
`--domain-rules-root`, сверяет inventory и копирование; integration package
содержит seed snapshot, а не независимый источник policy.
Проектные AGENTS, native sandbox и пользовательские указания наследуются.
Python покрывает окружение, воспроизводимость, тесты, типизацию и безопасность.
Sysadmin — диагностику, backup, проверку изменения и откат, включая ограничения
для сетевых каналов/Xray/Browbox. Личных путей и подключений в пресетах нет.

Для добавления новых managed mounts реализована отдельная явная миграция
`--previous-receipt ... --migrate-owned-fragments true`. Она проверяет прежний
receipt и пакеты, сравнивает старый/новый проверенные артефакты и делает
three-way merge только управляемых Cordis-блоков. Независимые пользовательские
правки сохраняются, конфликтующие изменения отклоняются. `!!js` разбирается
как непрозрачный scalar, не исполняется; YAML aliases и неизвестные tags
запрещены. Исходная конфигурация полностью сохранена в backup нового receipt.

Для дальнейшего отката использовать этот receipt и точные UI/policy артефакты;
не игнорировать пользовательские изменения в старой цепочке receipts.
