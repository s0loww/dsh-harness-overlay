# Память, исходная история и проверяемые уроки

## Панель настроек

Сетка SettingsPanel теперь выделяет меню отдельную колонку той же ширины,
что и само меню. Ранее фиксированные 238 px перекрывали родную колонку 188 px.
Это затрагивало все страницы настроек, особенно длинную страницу памяти.

Поля памяти выровнены вертикально; выбор сеанса и хранилища складывается в две
колонки при достаточной ширине. Кнопки чтения сохраняют фокус во время запроса,
индикатор и ответ занимают постоянное место рядом с действиями. Ошибки и пустые
наборы показаны явно. Поиск также сохраняет фокус, повторный запрос во время
ожидания не отправляется. У ответа есть собственная ограниченная прокрутка.

Cognee и Memoria выбираются явно. Панель Memoria читает только реально видимый
каталог MCP выбранного сеанса, показывает схемы и позволяет передать выбранный
вызов в чат. Наличие схемы не считается проверкой связи. Передача требует
подтверждения: это запрос к модели выбранного чата и штатные права/approval.
HTTP обработчик не выполняет MCP напрямую. Настройки MCP и секреты не переносятся.
Автоматического копирования записей между хранилищами нет.

## Исходная история

`history_search` и `history_read` работают с оригинальными событиями только
текущего чата, включая события до compact. Ограниченные страницы сохраняют ID
и смещения, исключают reasoning, inherited/recursive recall и известные секреты.
Это исторические данные, а не дополнительные инструкции. Первоначальная загрузка
native SessionQuery остаётся обязанностью хоста; собственный retained snapshot
ограничен, поэтому неполный поиск явно сообщает `truncated`.

## Проверенные уроки

`airules_knowledge` ведёт кандидатов в текущем сеансе: draft, review, approved,
stale/superseded. Одобрение связано с реальным последующим сообщением пользователя,
точной ревизией и одноразовой строкой. Модель не может одобрить сама себя.
Cognee publish использует существующий `airulesMemory` и его долговременный журнал;
upload не означает индексирование. Memoria и патч airules имеют отдельный явный
предпросмотр, без автоматической записи или применения правил. После перезапуска
кандидата восстанавливают из native tool log и проверяют заново — отдельная база
знаний не создаётся.

## Общие правила

В canonical airules 0.14.0 адаптированы существующие навыки `handoff`,
`memory-workspace`, `skill-maintainer` и их узкие references. Новые native имена
инструментов не навязаны другим хостам. Встроенный rulepack остаётся нижним слоем;
проектные правила и машинные настройки сохраняют установленный приоритет.

Реальный deploy 1С и загрузка реальных проектных фактов при этой доработке не
запускаются. Модельные оценки и детерминированные fixture-прогоны различаются
в интерфейсе инструментов и отчётах.

## Следующая итерация политики памяти

Переключатель панели пока выбирает хранилище для операции и не является общей
политикой агента. `airules_memory` обслуживает Cognee; Memoria ветка показывает
MCP-схемы и передаёт запрос в чат. Общего typed Memoria adapter и режима чтения
обоих источников здесь ещё нет.

По предложению пользователя следующая версия должна хранить глобальный режим
Cognee / Memoria / обе с проектным переопределением; чаты наследуют проект.
Сеанс остаётся исполнителем с native правами. Для «обе» нужны отдельные provenance
и статусы источников, явные назначения записей и receipts, без слепого копирования.
Обработка Cognee должна выбирать установленные локальные модели или OpenRouter
отдельно для эмбеддингов и извлечения связей. Утверждение `localProcessing`
заменяется явным профилем обработки. Эта новая политика пока не применена.
