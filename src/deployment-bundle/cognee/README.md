# Cognee component for the complete DSH package

Dependency-free ESM adapter; requires the package's Node runtime and an already
available local Docker Linux engine with Compose v2. Docker Desktop setup is a
separate prerequisite handled by the outer installer. This component never
restarts Docker Desktop, WSL, another container, or an existing Cognee instance.

```js
import { createCogneeAdapter } from './adapter.mjs'
const cognee = createCogneeAdapter()
const prerequisite = await cognee.detect()
const installed = await cognee.install({
  stateRoot: 'C:/Users/Example/AppData/Local/Airules/runtime/cognee',
  assetsRoot: 'E:/DSH-package/payload/cognee',
  port: 18080,
  ownerSid: 'S-1-5-21-111-222-333-1001', // current Windows user, not the builder
})
```

`install` accepts a new empty state directory only. A used port, foreign Docker
name, changed asset, unexpected model snapshot or symlink is refused. It returns
machine-local `configPath`, `authPath`, `processingBindingPath`, `processingPath`
under `memoryHome`. The outer receipt-based installer adopts these files into
the actual DSH profile without reading their secrets into logs or bundle files.
The binding keeps `composeDir` at the installed component state directory.
On Windows pass the current user's SID so native DSH profile application can
protect `.env` and its backups using the existing ACL code.

Other methods: `start({stateRoot})`, `health({stateRoot})`, `stop({stateRoot})`,
`uninstall({stateRoot,purgeData:false})`. Uninstall stops/removes only resources
whose ownership label matches the receipt. It retains the data volume by
default and never removes a shared image. `purgeData:true` explicitly deletes
the owned volume; machine receipt/config files remain for outer-installer
receipt handling and recovery.

## Offline payload boundary

`exportOfflineAssets({destination,sourceContainer})` is a build-machine operation.
The allowlist for the outer builder is **exactly**:

- `assets.json`;
- `cognee-image.tar`;
- `cognee-models.tar`.

The image is a pristine official pinned image, not a container export. Models
are public pinned snapshots from `lock.mjs`. Only regular model/tokenizer files
and generated `refs/main` are archived. HF blob symlinks are dereferenced inside
the model root; cache locks, xet logs, database directories, notes, local `.env`,
passwords, API keys and source-user datasets are excluded. Hashes and exact model
revisions are verified before loading/seeding. A fresh volume gets model files
only; databases and API credentials are generated on the recipient computer.

Actual build assets are stored outside source control under
`var/deployment-assets/cognee`. Do not package its sibling diagnostics, the
existing `D:/AI_Projects/cognee_local`, a Docker volume export, or smoke runtime
directories.

The server uses authenticated multi-tenant mode and a newly registered normal
DSH user. Its API key is generated by that fresh server and is written to the
recipient's private `auth.json`; the initial user's password is discarded after
provisioning. Four server secrets are random per installation. All ports bind
to `127.0.0.1`.

## Models and optional profiles

Default: CPU GLiNER demo `fastino/gliner2.5-base-v1` plus fastembed
`BAAI/bge-small-en-v1.5`, 384 dimensions. The latter is English; packaging and
offline execution do not establish Russian/1C retrieval quality. Model files
are already present; HF offline flags prevent an implicit download. Generated
answers and feedback are disabled and no paid provider key is supplied.

Normal installation uses a bridge network to remain compatible with the DSH
settings for OpenRouter, Ollama and LM Studio. Those providers are optional and
use the existing explicit profile/key configuration and native approval flow.
No external provider is enabled by this installer. For a fully isolated local
instance, `offline:true` keeps Cognee exclusively on an internal Docker network.
Docker Desktop does not publish an internal-only container's ports, so a second
small stdlib Python relay publishes the loopback API and forwards only to
`cognee:8000`. It handles no models, credentials or files. Optional external or
host model providers then require deliberately reinstalling the component with
suitable network access, not merely changing a model name.

`smoke.mjs STATE_ROOT REPORT_PATH` only accepts an isolated offline test instance
on a port other than 18080. It verifies empty storage, authentication, upload,
actual local extraction/embedding, query/graph and stop/start persistence. It
always stops that owned test instance afterward. It never uses existing user
data or paid inference. See the repository deployment report for actual results.
