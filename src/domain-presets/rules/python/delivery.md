# Реализация и проверка Python

Воспроизведи проблему через публичный интерфейс или существующий пользовательский сценарий. Разбери вызывающий код, контракты данных и существующие тесты. Согласуй сложное изменение с архитектурой проекта; для ясной локальной правки не вводи лишние уровни абстракции.

Сохраняй совместимость объявленной версии Python. Соблюдай существующие соглашения об ошибках, логировании, синхронном и асинхронном коде. Для I/O используй таймауты и закрытие ресурсов; не блокируй event loop синхронными долгими вызовами. Не проглатывай исключения, выдавая ложный успех. Не добавляй неограниченные повторы и не скрывай отмену.

Проверяй изменённое поведение на правильной границе: CLI, функция публичного API, HTTP или хранилище. Для исправления воспроизведи регрессию до правки, если это практически возможно. Моки ставь на внешние границы; они не должны повторять алгоритм проверяемого кода. Проверяй ошибки, пустой ввод и существенные побочные эффекты. Не заводи бессмысленный тест только на наличие строки и не создавай новый тестовый стек ради косметики.

Запускай принятые проектом тесты, линтер и проверку типов доступными инструментами. Сначала целевые проверки, затем обязательный набор CI. Не объявляй непройденную проверку успешной и не делай массовый autofix посторонних файлов. Типизация должна отражать контракт; не подавляй ошибки бесконтрольным Any или ignore.

Проверь опасные границы: ввод в subprocess и SQL, десериализацию, пути и архивы, права временных файлов, обработку секретов. Не используй shell=True с недоверенным вводом, eval или небезопасную загрузку pickle/YAML для внешних данных. Конкретный выбор библиотек и версий проверяй по актуальной официальной документации, когда это требуется задачей.

Сделай итоговый review diff: функциональность, совместимость, безопасность, тесты и отсутствие посторонних изменений. Отчёт: результат, команды проверки и их исход, существенные ограничения. Приложи доказательства поведения, а не только описание кода.
