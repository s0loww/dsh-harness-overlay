# Окружение Python

Сначала прочитай проектные инструкции, pyproject.toml, lock-файл, конфигурацию CI и команды разработки. Определи поддерживаемую версию Python, рабочий каталог, структуру пакетов и способ запуска. Не импортируй исполняемый модуль для простой проверки его наличия.

Проверь доступные интерпретаторы и инструменты командами чтения состояния. Не считай uv, Poetry, pytest, Ruff, mypy, Docker или доступ к сети установленными по названию пресета. Используй уже принятый менеджер и lock-файл; не меняй менеджер зависимостей и не обновляй весь граф ради одного исправления.

С uv используй существующий проектный workflow и frozen/locked режим, когда он поддерживается проектом. При обычном venv создавай отдельное проектное окружение при необходимости и используй его интерпретатор через полный путь. Ставь пакеты через выбранный python -m pip, а не случайный pip из PATH. Не ставь зависимости в системный Python и не отключай защиту управляемого системного окружения.

Изменяя зависимости, синхронизируй объявление и lock-файл поддерживаемой командой проекта; отдельно проверь совместимость Python и платформы. Не исполняй непроверенные установочные скрипты из сети и не открывай секретные URL частного индекса в отчётах. Для нативных расширений проверь необходимые компиляторы, колёса и платформенные ограничения.

Не включай .venv, кэши, токены и локальные конфиги в изменения. В PowerShell запускай команды с его синтаксисом и правильно цитируй пути; не переносись автоматически на bash-команды. Завершая работу, укажи фактически использованный интерпретатор, среду и непроверенные ограничения.
