# AIRules MCP Manager

Самостоятельная страница настроек MCP на основе MIT-пакета dsh-mcp-manager 0.6.0. Пакет не имеет внешних npm-зависимостей времени выполнения; использует штатные службы DSH `tools`, `webServer`, `connection` и клиентские locale/UI slots.

Подключение: отдельный модуль `airules-dsh-mcp-manager`. Клиент автоматически регистрирует полную `settings.section` с исходными формами серверов, подключения, OAuth и инструментов. HTTP-маршруты находятся под `/airules/mcp-manager`.

По умолчанию серверов нет, внешние подключения не создаются. Конфигурация хранится независимо от проекта в `$DSH_HOME/airules-mcp-servers.json`; существующий `mcp-servers.json` и проектные MCP-файлы не импортируются. Настроенные пользователем включенные серверы подключаются при следующем запуске. `enabled:false` исключает подключение. Файл записывается атомарно; Windows ACL разрешает доступ текущему пользователю и SYSTEM, POSIX использует режим 0600. Заголовки и OAuth-токены необходимы менеджеру и хранятся в этом защищенном локальном файле.

Чтение настроек требует штатного допуска соединения DSH. Изменения дополнительно требуют CSRF-токен, который клиент получает с допущенным запросом. Стандартный Desktop origin поддерживается. Локальный GET OAuth callback имеет единственное исключение: точное существующее случайное состояние не старше пяти минут, одноразовое даже при неудаче. Произвольный callback не открывает административные маршруты. Ответы ошибок и журналы не отражают исходные исключения или учетные данные.

Инструменты подключенных этим менеджером серверов доступны модели только в пресете `1c-airules`, явном штатном BUILD и разрешенном рабочем каталоге либо полном штатном доступе. Неизвестные режим, каталог или права запрещают вызов. Проектные инструменты этот фильтр не меняет. Более строгий фильтр нужен для общего менеджера: семантика произвольного стороннего MCP-инструмента заранее неизвестна.

Мобильный relay должен запрещать весь `/airules` (включая этот менеджер). Проектные серверы фасада, Memoria и прочие подключаются отдельно; никаких адресов, секретов или существующих привязок в пакет не включено.

Проверка: `node --test tests/mcp-manager-runtime.test.mjs`. Проверки используют реальный адаптированный движок и временный локальный файл; внешних MCP-подключений или OAuth-авторизации не выполняют.
