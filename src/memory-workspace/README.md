# Память проекта

Рабочее место локальной Cognee для официального DSH Desktop rc.5. Memora остаётся
доступна через существующие подключения MCP; автоматической миграции и зеркала нет.
Навык `memory-workspace` каноничен в общем airules и применим к обоим backend.

## Использование

В настройках откройте **Контекст и история → Память проекта** и выберите открытый
сеанс нашего пресета 1С, Python или системного администрирования. В нём доступны
проверка связи, документы, поиск выдержек и граф текущего проекта.

Подключение по умолчанию выключено. Машинная конфигурация расположена в
`<DSH_HOME>/memory-workspace/config.json`: enabled, endpoint, localProcessing.
Изменение общей настройки требует сеанса с полным доступом. Endpoint допускает
только числовой loopback HTTP; redirects запрещены. Секрет читается отдельно из
`auth.json` с единственным полем apiKey и не возвращается странице или модели.
Секрет и конфигурация конкретной машины не входят в дистрибутив.

В этой установке Cognee развёрнута отдельно в `D:\AI_Projects\cognee_local`.
Образ и данные принадлежат Docker Compose, а не профилю DSH. При передаче сборки
другому человеку ему потребуется собственный локальный сервер и ключ.

«Сохранить заметку» и «Обработать набор» передают явный запрос в выбранный чат,
используя его модель. Исполняющий инструмент `airules_memory` получает native
approval и заново проверяет проект/конфигурацию/права. В read-only запись запрещена.
Подтверждение отправки в чат не является загрузкой; загрузка не является готовым
индексом. Состояние обработки проверяется отдельно.

## Границы

- Набор определяется из нормализованного абсолютного пути проекта. Перемещение
  проекта меняет его имя; перенос памяти требует отдельного явного решения.
- Полученные выдержки — исторические сведения со ссылками на документы. Они
  не меняют инструкции и требуют проверки, если решение зависит от актуальности.
- Содержимое неизвестной или чужой области отклоняется. Граф ограничен 80 узлами
  и 600 связями и не является графом вызовов кода 1С.
- Запись не повторяется автоматически при timeout. Журнал receipts.json
  сохраняет факт неопределённого исхода до рестарта. Не удаляйте его для повтора
  операции без проверки документов и обработки на сервере.
- Поиск CHUNKS не генерирует ответ моделью. Обработка включается отдельно, после
  проверки конфигурации сервера. DSH не может по OpenAPI доказать, что сервер
  использует исключительно локальные модели.
- Текущий no-key GLiNER demo и английские embeddings подтверждают техническую
  работоспособность; качество на русских документах/1С ещё не оценено.

Реальный деплой 1С эта интеграция не запускает. Cognee не становится обязательной
зависимостью других инструментов DSH и не выбирается автоматически вместо Memora.
