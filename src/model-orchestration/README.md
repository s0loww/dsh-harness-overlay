# Модели для ролей 1С и ротация

Standalone package, official DSH 0.2.1-rc.5 / Cordis 4.0.5. No supplier modules, rules or private services copied. Audited supplier model-orchestration.js (7 generic workflow roles and private account/routing hooks); this package instead binds the exact 13 project_rules/overlays/1c/agents roles. All role mappings initially inherit; all rotation pools are absent/off. No login, catalog refresh, remote request or CLI bootstrap on boot.

Host mount: `airules-dsh-model-orchestration` provides `airulesModelOrchestration`, registers virtual LLM provider `airules-rotation`, settings sections `airules-role-models` / `airules-model-rotation`, and native-admission + CSRF HTTP control `/airules/model-orchestration`. Data persists under `dshHomePath('model-orchestration/settings.json')`; credentials are never stored here.

1C composition mount: `airules-dsh-model-orchestration/delegation`, config `{rulepackRoot: absoluteEmbeddedRulepackPath}`. Uses existing public `airules-dsh-provider/core` exports `loadRulepack/readRole` to verify personas. Registers **airules_delegate(role,task,cwd?)**, calls native `parentAgentOptionsForDelegation`, `llm.resolveCallConfig`, then `subagents.startActivation` with real `agentOptions` and the native depth budget. Uses independently composed `spawn`; does not modify permissions, native tools, model-selection policies or other presets. Roles are persona contracts, not native execution providers. A bare persona prompt does not select a model.

Rotation pools require at least two distinct models from one provider and the exact same registered adapter, verified common protocol and compatible modalities/update capabilities/efforts. Protocol evidence is supported for official PiAiAdapter (model.api) and this distribution's CodexAdapter. Other protocols fail closed. Pool context is the smallest member context, efforts the intersection, and the virtual route explicitly supports **text only**. Select a direct model for images. Native prepared calls retain request controls and bind dispatch to their registration.

New session model selection is round-robin. Pin state persists across restarts. Following any emitted chunk, the session keeps its model across subsequent turns and tools. Optional failover is allowed only before any output and only for explicit transient transport/rate/quota error codes; auth, policy, context, cancellation, incomplete streams and unknown failures are not retried. No replay of a partial answer. Deleting/changing a pinned member fails that old session rather than switching its model. Pools cannot contain other pools. Native middleware and permissions remain in force. Pins are capped at 2048 sessions; capacity exhaustion fails closed.

Limits: single adapter/protocol pools, no cross-provider switching; no automatic credential/account rotation; no usage probing, cheap-model classifier, supplier ACP/CLI orchestration, or background auth discovery. Existing account pooling in subscriptions remains separate. Settings/catalog actions happen only through an authenticated UI action. Tests do not make inference or paid requests.
