# Специализированные инструменты 1С

Хранилище конфигурации, локальное сравнение XML-выгрузок и связующий исполнитель
для явно настроенных repo-ops/v8unpack. MCP-фасад не требуется.

Страница «Хранилище и обновления» использует выбранный открытый native-сеанс с
пресетом 1С. Сравнение читает две либо три выгрузки внутри проекта; оно показывает
группы изменённых файлов и план расширения, не применяет MergeCfg/CFE к базе и не
подтверждает состояние поддержки.

Проектный binding — `.dsh/onec-specialized.json`; драйвер готового связующего
скрипта — `.dsh/onec-specialized-driver.json`. Страница может скопировать точные
байты штатного связующего скрипта в `tools/onec-specialized/runner.mjs`, не запуская
его. Интерпретаторы и доверенные SHA-256 внешних скриптов задаются отдельно в
параметрах встроенного плагина. Пароли в этих настройках не размещаются.

План привязан к исходникам, binding, драйверу и зависимостям. Выполнение передаётся
в выбранный чат и проходит через штатные sandbox/subprocess и approval DSH.
Готовый bridge вызывает PowerShell/Python непосредственно через native process
adapter; вложенный spawn из confined Node не используется. Exit 0 без свежего
связанного отчёта не считается успехом. Фикстуры всегда отмечены, PASS процесса
не означает проверку реальной конфигурации или базы.

Подробный протокол и ограничения описаны в `docs/onec-specialized-port.md` основного
репозитория сборки. Реальный деплой этим компонентным тестированием не запускался.
