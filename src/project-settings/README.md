# Настройки проекта 1С

Отдельная реальная страница `settings.section`, id `airules-onec-project`.
Нативный список сеансов определяет выбранный проект; если активного нет,
можно выбрать уже существующий сеанс из списка. Host принимает только
sessionId и определяет cwd из native session metadata. Произвольный путь
из браузера не принимается. Чтение не создаёт и не меняет файлов.

Поддерживается совместимый ограниченный набор ключей `.dev.env`: база,
платформа/EDT, каталоги исходников, расширения, префикс и авторство.
Это редактор параметров: он не подключается к базе и не выполняет deploy,
проверки, команды, COM или изменение MCP. Неизвестные ключи сохраняются,
но не возвращаются клиенту. Новые значения по умолчанию не придумываются.

IB_PASSWORD и IB_UNLOCK_CODE доступны только для записи с признаком
«задано». Существующие пароли и коды в браузер не передаются. Старые
INFOBASE_PATH с Pwd/Password и URL публикации с userinfo целиком скрываются,
оставаясь в файле до явной правки. Новый пароль задаётся отдельно.

Сохранение принимает только изменённые ключи, проверяет HMAC revision
прочитанного файла и отказывает при конфликте. Сохраняются порядок,
неизвестные строки, полные строки комментариев, BOM, LF/CRLF и дубликаты
неизменённых полей; дубликаты изменяемого ключа обновляются все. Формат
чтения совместим с Oleg parseDevEnv: парные внешние кавычки снимаются,
значения не интерполируются; inline `#` является частью значения.
Неподдерживаемая кодировка/бинарный файл отвергаются.

На Save исходник копируется до замены в
`$DSH_HOME/project-settings-backups/<sha256-normalized-project-root>/*.env`.
Файлы и директории защищены ACL текущего пользователя Windows, либо
0600/0700 на Unix; временный файл защищается до записи секрета. Затем
fsync + atomic rename. Существующие файлы-ссылки и junction roots запрещены.
Lock исключает одновременные записи этого редактора; сторонний редактор
не разделяет lock, поэтому CAS повторно проверяется перед rename.
Gitignore, project MCP и любые другие проектные файлы не изменяются.

Авторизация: native connection fence для всех запросов, отдельный CSRF
для Save. native sandboxPolicy обязателен; read-only допускает чтение,
workspace-write/danger-full-access — сохранение в точном session cwd.
У закрытого сеанса безопасно восстанавливается native sandbox projection
через read-only persistence handle и public projections.restore. История
ограничена 20000 событиями; слишком большой сеанс надо открыть. Обрезанная
история не используется для вывода о разрешении записи. Attached agent
для редактирования не требуется.

Дополнительный peer: встроенный `@deepseek-ai/dsh-home-paths@0.2.1-rc.5`.
Проверка: `node --test tests/project-settings.test.mjs`.

## Среда и помощник существующего проекта

Отдельная страница «Среда 1С» (`airules-onec-environment`) и блок помощника
на странице проекта запускают обнаружение только по кнопке. GET
`/airules/project-settings/environment?sessionId=...` читает стандартные
локальные каталоги платформ 1cv8/1cv8_x86 в Program Files и файлы
APPDATA/PROGRAMDATA `1C/1CEStart/ibases.v8i`, включая UTF-16.
К CommonInfoBases, реестру и сетевым каталогам по ссылкам обращения нет.
Из Connect допускаются только File либо Srvr/Ref; реквизиты доступа,
прочие поля каталога и параметры запуска не возвращаются в браузер.

Статус исходников ищет Configuration.xml/Configuration.mdo внутри session
cwd, включая настроенный EXPORT_PATH только если он остаётся внутри проекта.
Стандартные каталоги/PATH проверяются на наличие Git, Java, BSL LS и EDT;
компоненты EDT дополнительно ищутся в стандартных корнях 1C/1CE.
Наличие исполняемого файла не утверждает его работоспособность.
Процессы 1С и инструменты не запускаются, подключения к базе не создаются.

Выбор зарегистрированной базы и платформы добавляет только явно выбранные
несекретные поля в черновик. Предложение по исходникам/единственной платформе
имеет предпросмотр с изначально снятыми флажками. При нескольких платформах
или базах первая не выбирается автоматически. Только существующий Save
с теми же native permissions, CSRF и CAS изменяет .dev.env. Помощник не
создаёт проект, базу, rules/skills/MCP или конфигурацию харнесса.

Проверки среды: `node --test tests/project-environment.test.mjs`.
