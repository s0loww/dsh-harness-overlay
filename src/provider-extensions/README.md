# Google / Muse: отдельные runtime и вход

Пакет добавляет холодную настройку двух подписочных провайдеров. На старте не запускает CLI, не скачивает runtime и не импортирует аккаунты. Установка внешнего runtime остаётся отдельным явным действием; в карточке нужны абсолютный путь к исполняемому файлу и SHA-256 из доверенного манифеста. Для Google нужны Antigravity ACP server и его аргументы запуска, обычный Gemini CLI не подходит. Для Muse нужен официальный Muse CLI с MSP и ACP.

Loader entry: `name: airules-dsh-provider-extensions`, inject `configEditor,dshHomePath`. Зависимости должны быть разрешены до включения пакета; публичный `@zaimokuza/dsh-acp-adapter` уже смонтирован ровно одним Loader entry. Требуется существующая политика `airules-dsh-acp`: она допускает внешний runtime только в разрешённой сессии 1С, в режиме разработки и с Native Agent Access. Пакет разрешения не меняет.

`DriverSettings({providerId:'google'|'muse'})` и `DRIVER_PROVIDERS` экспортируются для общей страницы провайдеров. Fallback: `airules-provider-drivers`. HTTP `/airules/provider-drivers` требует штатный connection admission, CSRF для POST и ограничивает JSON 12 KiB. Ошибки SDK и stderr не публикуются.

1. Пользователь устанавливает runtime и получает доверенный SHA-256.
2. «Проверить и сохранить runtime» проверяет файл, digest и аргументы, отключает только соответствующий профиль ACP.
3. «Войти отдельно» запускает Google Antigravity OAuth либо Muse MSP device flow в собственном домашнем каталоге `dshHomePath('provider-drivers')`. На Windows Google runtime сам открывает браузер и обрабатывает loopback callback. Native Google SDK предоставляет ручной headless callback на Linux; поле появляется только по его запросу. В закреплённой версии Google SDK Windows headless capture отсутствует. Есть отмена и предел ожидания10минут.
4. «Проверить вход» проверяет локальный Google grant либо вызывает официальный Muse MSP account/read и model/list. Никаких аккаунтов из пользовательских CLI-каталогов.
5. «Включить ACP» добавляет `airules-google` или `airules-muse` в общий штатный ACP adapter через `configEditor.edit`; остальные профили и явно выбранная глобальная approval policy сохраняются. Если policy отсутствует, для первоначальной настройки используется `ask`. Native ACP отвечает за модели, сессии, tools, permissions, отмену и generation. Перед каждым запуском wrapper повторно сверяет SHA-256 runtime, очищает окружение и передаёт stdio native ACP.
6. «Выключить ACP» удаляет только собственный профиль. «Выйти» сначала отключает профиль, затем очищает собственный Google grant либо отсоединяет собственный Muse HOME переименованием в защищённый `muse-disconnected-<uuid>`. Это локальное отключение, не отзыв доступа на стороне Meta. Неподтверждённый по исходникам RPC logout не вызывается. Следующий вход создаёт пустой HOME; резервный каталог автоматически не импортируется.

Manifest содержит путь, digest и аргументы, но не токены. Manifest имеет ACL текущего пользователя/SYSTEM в Windows; домашний каталог авторизации получает наследуемый ACL тех же субъектов. API-ключи, ambient HOME, прокси с возможными секретами и настройки CLI в дочернее окружение не переносятся. Tokens принадлежат самому runtime и остаются вне Git. Генерация Muse запускается с `--no-session-log --disable-write --disable-shell`; разрешённые действия принадлежат штатному ACP bridge и его permission policy.

Проверки: `node --test tests/provider-extensions.test.mjs`. Fixture-тесты проверяют реальные файловые digest, composition с одним registry, MSP request methods и вход через явно заданную connectionFactory. Платные запросы, OAuth и установленный официальный CLI на пользовательском аккаунте автоматически не запускались. Ротация аккаунтов, квоты и автозагрузка бинарных runtime этим пакетом не реализованы.
