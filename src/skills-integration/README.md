# Навыки DSH

Настройки `airules-skills` используют штатный каталог `ctx.skills` выбранного
агента, включая его пресет. Инструкции загружаются только по запросу. Плагин
не устанавливает навыки сборки Олега и не добавляет MCP.

Поиск, общая/проектная область, просмотр инструкций, индивидуальное и массовое
переключение, создание нового `SKILL.md`, обновление и открытие каталога доступны
на одной странице. Импорт набора с дополнительными ресурсами выполняет соседняя
страница «Импорт из других агентов». После импорта событие
`airules-skills-changed` обновляет список.

Хранилища совпадают с DSH: `DSH_HOME/skills`, `DSH_AGENTS_HOME/skills`,
`<workspace>/.dsh/skills`, `<workspace>/.agents/skills`. Проектные записи имеют
нативный приоритет. Права берутся из выбранного настоящего сеанса DSH:
проектные изменения требуют записи в рабочую папку, общие — полного доступа.
HTTP требует штатную аутентификацию подключения и CSRF для действий.

При отключении файлового навыка исходные байты сохраняются как
`SKILL.md.disabled` (либо `<flat>.md.disabled`). Вместо исходного файла
создаётся штатная инструкция с `disable-model-invocation: true` и
`user-invocable: false`. Это сохраняет имя в каталоге и не позволяет незаметно
подхватить одноимённый встроенный навык. Включение проверяет SHA исходника и
восстанавливает точные байты. Дополнительные файлы навыка не изменяются и не
запускаются. Перед переключениями предыдущие инструкции защищаются в
`DSH_HOME/skills-backups`.

Для встроенных файловых навыков отключение создаёт пользовательское
переопределение в `DSH_HOME/skills`, которое имеет штатный приоритет над
`bundled`. Включение удаляет только созданное переопределение. Файлы установки
сохраняются. Навыки, зарегистрированные исполняемым кодом плагина (`runtime`),
доступны только для просмотра: их приоритет нельзя надёжно переопределить
пользовательским файловым навыком.

Если пользователь сам запретил оба вида вызова в исходном `SKILL.md`, карточка
показывает «Политика SKILL.md» и предлагает изменить исходную политику вручную.
Менеджер не снимает вручную заданный запрет переключателем.

Изменения проверяют ревизию файла, отвергают ссылки, жёсткие ссылки и выход
за управляемые каталоги. Страница не предоставляет произвольный файловый
редактор, запуск скриптов или подключение внешних каталогов.

## Назначения по задачам

Под списком навыков находится выбор типа текущей задачи и редактор назначений.
Используются 13 типов: analysis/planning/specification/architecture/implementation/
bugfix/spec-review/code-review/testing/verification/documentation/refactoring/
operations. Проверка по спецификации, ревью кода и тестирование разделены.
Дополнительные оси — точные 13 ролей нашей оркестрации и штатный режим доступа
read-only/workspace-write/danger-full-access. Пустая ось означает «все».

Приоритет данных: встроенные значения для 26 общих и предметных навыков
→ общие переопределения `DSH_HOME/skill-assignments/settings.json` →
проектные `.dsh/skill-assignments.json`. Неизвестные навыки не ограничиваются.
Сброс удаляет только выбранное переопределение и возвращает наследуемое значение.
Запись проверяет SHA-ревизию, ограничивает размер и сохраняет предыдущие данные
в `DSH_HOME/skill-assignments/backups`. Общие изменения требуют полного доступа,
проектные — записи в рабочую папку.

Выбор типа задачи — общая настройка проекта в `.dsh/skill-context.json`.
Все его чаты используют один выбор; изменение требует записи в проект и контекста
ведущего агента. Штатный plan mode и точная роль управляемого делегата имеют
приоритет над этим значением, затем применяется проектный тип (auto — все типы).
Выбор не меняет разрешения или plan mode. Роль извлекается только из первого
собственного нативного `subagent/descriptor` с меткой `airules-role:<точная роль>`
и provider spawn. Унаследованные события и строки сообщений не используются.
Например, tester → testing, code-reviewer → code-review, arch-reviewer → architecture.
Прежние `DSH_HOME/skill-assignments/sessions/<SHA session id>.json` сохранены,
но не импортируются автоматически: разные сеансы могли иметь несовместимые значения.


Runtime подключается к штатному `agent/pre-step` только для 1c-airules,
python-airules и sysadmin-airules. Каждый раз берёт полный scoped снимок реестра
и фильтрует только каталог описаний. Точный вызов `skill({name})` и доступ к полным
инструкциям не ограничиваются назначениями; политика SKILL.md остаётся решающей.
При неполном снимке новая подборка не публикуется; существующая история сохраняется.
Одинаковая принятая подборка не дописывается повторно. Смена задачи и перезапуск
могут расширить подборку обратно: ранее сокращённый каталог не служит источником.
Повреждённые настройки не заменяются и не блокируют работу: остаётся штатный
каталог, а интерфейс показывает ошибку.

HTTP `/airules/skills`: GET возвращает assignments, POST assignment-save сохраняет
или сбрасывает одно назначение, POST task-context меняет тип задачи. Все действия
используют штатную аутентификацию/CSRF и проверенный сеанс. Назначения не относятся
к MCP-фасаду, не устанавливают навыки и не запускают модель или скрипты.

Проверка: `node --test tests/skills-integration.test.mjs tests/skill-assignments.test.mjs`. Тест использует
настоящие `SkillRegistry`, `FileSystemSkillProvider` и `skill.execute` из
официальной версии 0.2.1-rc.5: отключённый навык отклоняется самим штатным
инструментом, после включения загружаются исходные инструкции.
